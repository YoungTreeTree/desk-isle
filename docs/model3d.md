# 3D 模型组件

3D 组件默认宽 8 格、高 12 格（320×480），可在网格内移动，改变屏幕方向时保持尺寸。模型之外的区域透明，透出壁纸和下层组件。旧的全屏布局仍可读取，并可通过「占格尺寸」改为 8×12 格。模型、贴图、节点动画和 Morph 动画在 ESP32-P4 上软件绘制。Mac 只准备和上传资源，随后发送重播／精度等控制，不连续传输画面。

## 使用

1. 在布局库新建布局，添加「3D 模型」，选择内置 BB8，或点击「导入 GLB…」选择本机模型。两种来源共用布局资产存储，导入时默认生成供开发板使用的「流畅版」。
2. 点击「应用到小屏」。组件随屏幕方向调整为全屏。
3. 在组件面板使用「重播出场」「读取性能」。精度可选原生、半分辨率、四分之一分辨率；更改后需要再次应用，占格尺寸不变。320×480 组件对应的内部精度为 320×480、160×240、80×120。

模型使用独立资源 UUID，原始 GLB 和转换包归档在本机 Application Support 的布局资产目录中。复制布局共享不可变资源；更换模型或切换细节产生新引用。保存草稿不会更新正在显示的模型。布局快照及备份参与资源回收，断线重连后恢复上次请求应用的模型。

「生成流畅版／恢复原始细节」始终从保留的原始 GLB 生成，切换后需要点击「应用到小屏」。已有模型不会在升级时自动减面。流畅版使用 meshoptimizer 在 Mac 上离线简化几何，锁定网格边界，将法线、UV 和所有 Morph 位移纳入误差计算，并用同一顶点映射保留这些属性。贴图、节点变换及四段动画的关键帧不因减面而删除。小于等于 12,000 三角面的模型直接保留；更大的模型以约 10% 面数为目标，同时限制误差，因此实际保留数量可能更高。简化会损失部分几何细节，面板中的三角面数量为实际上传值。

固件只包含渲染器，不包含任何角色模型。转换包通过 USB 或 CH343 分块上传到 PSRAM，不写 Flash。板子断电后需要重新上传。Mac 断开但板子仍有供电时，已上传动画可以独立运行；移除组件或切换到没有 3D 组件的布局时释放模型、深度缓冲和临时顶点数据。上传过程中保留旧画面，校验成功才替换运行实例。未完成的上传 30 秒后释放；熄屏时不继续绘制。

## 首版范围

- glTF 2.0 GLB，三角面、索引、法线，内嵌图片；最多 10 万三角面、15 万顶点、64 个节点／网格、8 张纹理，转换包不超过 8 MiB。
- 节点位置、四元数旋转、缩放，以及最多 4 个 Morph 位置目标。支持 LINEAR／STEP 动画及 sparse accessors。
- 识别 `appear`、`idle`、`blink`、`greet` 四个动画名称：出场完成后进入待机，自动眨眼；没有对应片段时使用静态节点姿态。
- 贴图最长边缩到 512 px，转为 RGB565。可在「流畅版」和「原始细节」之间切换；两者均保留原始文件和动画。
- 软件光栅化、深度缓冲、透视校正纹理和基本顶点光照。未实现 PBR、阴影、抗锯齿、透明材质、骨骼蒙皮、纹理变换、外部贴图或压缩扩展，不等价于网页的 Three.js 渲染效果。
- 组件背景透明遮罩由深度缓冲生成，不以模型颜色抠图；动画离开的位置恢复壁纸及下层组件。组件透明背景不等于支持模型内部半透明材质。
- Mac 编辑器及布局库使用静态组件示意，不启动另一套 3D 动画或渲染循环。

macOS 应用内置一份低面数 BB8，包含左右滚动和头部回摆动画；使用静态 PNG 展示选择预览，不启动实时渲染器。内置文件随应用资源包一起移动，选用后复制到布局库，后续升级不覆盖已保存布局的模型。波加曼及其他自定义文件不随应用分发。BB8 素材与项目代码的 MIT 授权范围分开，见[素材说明](../macos/Resources/Model3D/README.md)；自定义导入不改变素材原有的授权条件。

## 性能测量

面板显示帧率使用实际成功提交到面板的新 3D 帧计数，不把其他组件更新计入。绘制耗时包括动画求值、顶点变换、光栅化及必要的让出调度；它是墙钟耗时，不是系统 CPU 使用率。PSRAM 指标来自 ESP-IDF 堆统计。额外的 `DESKISLE_3D_PROFILE` 行提供动画、清屏、顶点、光栅化和合成分段计时，旧版统计读取端可以忽略它。

先从应用应用一套只有 3D 组件的布局，再运行：

```sh
python3 tools/model3d-benchmark.py --port /dev/cu.YOUR_CH343_PORT \
  --seconds 30 --scales 1 2 4 --output build/model3d/benchmark.json
```

需要 pyserial。脚本暂时接管 CH343，验证错误分块／损坏包不会替换当前模型，再分别测量三个精度，最后恢复原精度。`--stats-only` 仅读取当前计数；`--pack PATH` 可临时上传本机准备好的 D3M1 包，应用重连后恢复已保存画面。原生 USB 使用布局 CDC 端口并加 `--native-usb`，测试时关闭占用该端口的桌屿应用。

运行本机回归：

```sh
swift test
python3 tests/test_protocol.py
# 先设置 IDF_PATH，或载入 ESP-IDF 环境
python3 tests/test_model3d.py
```

渲染测试使用原创合成几何，无需下载或提交波加曼模型。可额外用 `tests/model3d_test.c` 检查本机转换后的真实模型。

### ESP32-P4 实测（2026-11-13）

CH343 单线连接，ESP32-P4 400 MHz、32 MiB PSRAM / 200 MHz；只有一个全屏 3D 组件。用户导入的原始模型有 85,936 三角面、48,019 顶点，运行包 4,528,292 字节。流畅版为 12,330 三角面、7,895 顶点，运行包 2,112,076 字节；两者均保留 3 张 512×512 RGB565 纹理与四段动画，模型不随仓库分发。

渲染器改为仅清理前一帧几何覆盖区域，并仅合成、放大变化区域；跳过零权重 Morph 运算，减少像素循环中的不变量读取和常见 UV 的取整运算。未减面的七个测试姿态与优化前逐像素一致；减面版会损失几何细节，但贴图、节点及动画轨道保持不变。

每档运行 30 秒，以下使用出场结束后的采样区间。降低内部渲染分辨率后，组件仍占满 1280×720。数字是当前实现的实测值，不是芯片性能上限或整机 CPU 使用率。

| 内部渲染分辨率 | 优化前原模 | 优化后流畅版 | 流畅版每帧绘制墙钟耗时 | 剩余 PSRAM |
| --- | ---: | ---: | ---: | ---: |
| 1280×720 | 2.12 FPS | 6.94 FPS | 127.93 ms | 14.61 MiB |
| 640×360 | 2.56 FPS | 11.77 FPS | 64.09 ms | 16.83 MiB |
| 320×180 | 2.92 FPS | 17.34 FPS | 42.04 ms | 17.83 MiB |

三档采样区间内 PSRAM 无持续下降；损坏上传和错误分块被拒绝，原运行模型保留。测试时应用让出串口，板子独立播放，测量脚本仅发送控制和读取计数。原生 USB 未在本轮真机测试。

减面与局部更新明显改善帧率，但尚未达到 30 FPS。当前主要开销仍是软件光栅化；低精度档还会明显损失清晰度。对于固定镜头和固定动作，离线预渲染动画帧是另一个方向，本轮未实现该播放方案。
